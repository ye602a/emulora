## 1. Make standalone renders and LUTs comparable · implemented

At the baseline, CLI `process` discarded the recipe on spectral initialization errors. `export-lut` always bypassed spectral calibration, disabled even local DIR and processed each grid node as a separate image. Emulora also accepted active UV/IR and adaptation surface fields without a spectral consumer. In the ordinary CPU fallback an active 135 border could disappear. FPW's versioned constructor and checked resident route have a different failure path.

The CLI now shares recipe/profile resolution between both commands. [Core baking](../crates/emulora-core/src/lut_bake.rs) uses the photo constructor, keeps fixed trims and local chemistry, renders one grid and isolates GPU photo caches. The CLI atomically publishes a completed cube. A render or write error preserves the previous file. The [usage guide](USAGE.md#spectral-cube-export) defines the transport and what is omitted. Old and new exports have different looks. Existing CUBE files remain standalone artifacts. For the next engine change, compare against the pointwise photo on the **same backend** and distinguish exact grid nodes from interpolation on off-grid samples. [Batch measurements](ENGINE_STUDIES.md#spectral-cube-export)

OFX keeps local DIR in `lutSafeParams` and renders a whole grid. Python's reference tests permute neighbourhoods and exercise scene-wide dependencies. Emulora specifically gates frame-normalized highlight boost and both scan glare sources. A fixed manual print shift or preflash is part of the requested look in Emulora. Python experimental's neutral-bake convention also clears such per-image trims. [OFX source](https://github.com/chaert-s/spektrafilm-ofx/blob/86476af/src/SpektraFilmPlugin.cpp) · [Python bake tests](https://github.com/andreavolpato/spektrafilm/blob/28bf883/tests/test_lut_mode.py)

## 2. Give calibration changes one owner · implemented in Emulora and the standalone GUI

The [spectral constructor and checked refresh](../crates/emulora-core/src/pipeline.rs) now share the calibration identity. Changing film density gamma affects midgray calibration, even though the GUI has no slider for it. Camera EV enters that identity only when print exposure compensation is enabled. Development times, spectral preparation, enlarger light/filters and preflash are also tracked. A dispatch-only edit can reuse prepared data. The [GUI](../crates/emulora-gui/src/main.rs) retains the effective film/paper identity and asks Emulora about the recipe. On a miss it rebuilds from the original profiles and reports build errors. A host replacing profiles, resource packs or the accepted setup must discard the corresponding cached pipeline.

[Refresh regressions](../crates/emulora-core/tests/calibration_refresh.rs) compare a warm and fresh CPU print on the same RGB patch, check a gamma-dependent midgray factor, and exercise both compensated and uncompensated EV. A matching database neutral row survives refresh from a raw recipe. If the optional table or row is missing, manual values enter calibration. A present but malformed or unreadable table now fails the build with its path. The GUI binds glare to the material being scanned and hides enlarger and print-curve controls on a direct scan. Switching routes retains the two glare settings.

FPW main keys the pipeline by film, paper, route, contract and resource directory. For a matching key, the host passes the requested parameters to Emulora checked refresh and rebuilds if calibration changed. The host disables print exposure compensation. The [resident negative cache](../crates/emulora-gpu/src/negative_cache.rs) continues to compare prepared density dependencies. The [physical stock defaults](maintenance/HOST_GPU_INTEGRATION_CONTRACT.md#physical-stock-defaults) covers constructor order and route identity.

Batch verification on Windows used the default precision. The core library, refresh and stock-setup suites passed (43 + 3 + 4 tests). An offscreen egui frame sequence checked the controls for film scan, paper print and film scan again. All five existing `calibrated_output_v1` tests passed with `EMULORA_REQUIRE_GPU=1`, including the resident physical negative route. The RGB patch parity check ran on CPU. This batch did not run a fresh photographic acceptance set or a preview performance benchmark.

Further input work remains separate. The Hanatos adaptation window runs today. Camera UV/IR transmission now uses the stock reference light during spectral preparation. The optional [Hanatos stock colour correction](ENGINE_STUDIES.md#hanatos-stock-colour-correction-on-still-photographs) uses the 20 eligible filming profiles. Keep spectral Gaussian blur at zero after the [five-stock photo study](ENGINE_STUDIES.md#hanatos-wavelength-smoothing-on-still-photographs). The [reconstructed-white trial](ENGINE_STUDIES.md#reconstructed-white-normalization-on-negatives-and-prints) removed the window-induced gray exposure drift. Keep the current print packs and FPW v1 look together. A future calibration revision needs its own fitted print packs and saved-photo qualification. Nonzero blur and encoded camera input still fail spectral construction. Input gamut compression is baked into Hanatos/Arctic tables. Mallett uses a matrix. The monochrome camera filter and its neutral exposure policy are documented below.
