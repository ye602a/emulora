## 1. Make standalone renders and LUTs comparable · implemented

At the baseline, CLI `process` discarded the recipe on spectral initialization errors. `export-lut` always bypassed spectral calibration, disabled even local DIR and processed each grid node as a separate image. RS also accepted active UV/IR and adaptation surface fields without a spectral consumer. In the ordinary CPU fallback an active 135 border could disappear. FPW's versioned constructor and checked resident route have a different failure path.

The CLI now shares recipe/profile resolution between both commands. [Core baking](../crates/spektrafilm-core/src/lut_bake.rs) uses the photo constructor, keeps fixed trims and local chemistry, renders one grid and isolates GPU photo caches. The CLI atomically publishes a completed cube. A render or write error preserves the previous file. The [usage guide](USAGE.md#spectral-cube-export) defines the transport and what is omitted. Old and new exports have different looks. Existing CUBE files remain standalone artifacts. For the next engine change, compare against the pointwise photo on the **same backend** and distinguish exact grid nodes from interpolation on off-grid samples. [Batch measurements](ENGINE_STUDIES.md#spectral-cube-export)

OFX keeps local DIR in `lutSafeParams` and renders a whole grid. Python's reference tests permute neighbourhoods and exercise scene-wide dependencies. RS specifically gates frame-normalized highlight boost and both scan glare sources. A fixed manual print shift or preflash is part of the requested look in RS. Python experimental's neutral-bake convention also clears such per-image trims. [OFX source](https://github.com/chaert-s/spektrafilm-ofx/blob/86476af/src/SpektraFilmPlugin.cpp) · [Python bake tests](https://github.com/andreavolpato/spektrafilm/blob/28bf883/tests/test_lut_mode.py)

## 2. Give calibration changes one owner · implemented in RS and the standalone GUI

The [spectral constructor and checked refresh](../crates/spektrafilm-core/src/pipeline.rs) now share the calibration identity. Changing film density gamma affects midgray calibration, even though the GUI has no slider for it. Camera EV enters that identity only when print exposure compensation is enabled. Development times, spectral preparation, enlarger light/filters and preflash are also tracked. A dispatch-only edit can reuse prepared data. The [GUI](../crates/spektrafilm-gui/src/main.rs) retains the effective film/paper identity and asks RS about the recipe. On a miss it rebuilds from the original profiles and reports build errors. A host replacing profiles, resource packs or the accepted setup must discard the corresponding cached pipeline.

[Refresh regressions](../crates/spektrafilm-core/tests/calibration_refresh.rs) compare a warm and fresh CPU print on the same RGB patch, check a gamma-dependent midgray factor, and exercise both compensated and uncompensated EV. A matching database neutral row survives refresh from a raw recipe. If the optional table or row is missing, manual values enter calibration. A present but malformed or unreadable table now fails the build with its path. The GUI binds glare to the material being scanned and hides enlarger and print-curve controls on a direct scan. Switching routes retains the two glare settings.

FPW main retains its published RS pin and host `PipelineKey`. The batch-10 adoption branch keeps immutable input and resource identities and uses RS checked refresh for recipe changes. The host already disables print exposure compensation before patching camera EV at dispatch. Its current path has no established stale-gamma failure. The [resident negative cache](../crates/spektrafilm-gpu/src/negative_cache.rs) continues to compare prepared density dependencies. The [accepted stock setup contract](maintenance/FPW_ACCEPTED_STOCK_SETUP_V1.md) covers constructor order and route identity.

Batch verification on Windows used the default precision. The core library, refresh and stock-setup suites passed (43 + 3 + 4 tests). An offscreen egui frame sequence checked the controls for film scan, paper print and film scan again. All five existing `calibrated_output_v1` tests passed with `SPEKTRAFILM_REQUIRE_GPU=1`, including the resident physical negative route. The RGB patch parity check ran on CPU. This batch did not run a fresh photographic acceptance set or a preview performance benchmark.

Further input work remains separate. The Hanatos adaptation window runs today. Active UV/IR transmission, the adaptation surface, spectral Gaussian blur and encoded camera input currently fail spectral construction. Input gamut compression is baked into Hanatos/Arctic tables. Mallett uses a matrix. The monochrome camera filter and its neutral exposure policy are documented below.

## 3. Deliver resources with their photographic process

**Portra NC/VC packaging is pending an explicit data grant.** At LAB main `b51e672`, all four profiles' license fields point to E-190 and the product notice. Release `f61769b` introduced them. The [project notice](https://github.com/JamesQiu2005/SpektraLab/blob/b51e672/license/NOTICE.md) identifies the product data separately, the [bundled license guide](https://github.com/JamesQiu2005/SpektraLab/blob/b51e672/modern_UI/Spektrafilm/Spektrafilm/Resources/Licenses/README.txt) identifies the 28 upstream profiles and their derivatives, and the [product notice](https://github.com/JamesQiu2005/SpektraLab/blob/b51e672/engine/resources_product/NOTICE.md) records how the new data was made. We found no explicit redistribution terms for the four JSON files and their separately fitted 32 rows. Resume packaging when the terms cover both. The older permission recorded for a particular B&W revision applies to those earlier assets.

The four E-190 profiles include measured sheet curves, reconstructed dyes, extrapolated tails and fitted adaptation. LAB main carries a second file with 32 TH-KG3 film/paper rows, merged only into missing entries. Its digitizer/build inputs are described as untracked. The product notice distinguishes these files from the original CC BY-SA profile set. Record redistribution terms for this revision separately from the older B&W study.

In a temporary RS resource directory we ran all four films on Portra Endura using CPU f32 Hanatos and the same near-18% patch. Generic filter numbers produced a linear RGB max-minus-min of **0.1552–0.1762**. With the corresponding LAB row it was **0.00051–0.00054**. Settings used a neutral sRGB PNG code 118, manual exposure, local DIR, linear sRGB output and disabled optics/grain/glare. This validates the transfer of those four rows on one paper. Before packaging, verify all pairings, distinguish NC/VC from modern Portra across exposure and saturated colours, and preserve the existing resource identity. [Product data and provenance](https://github.com/JamesQiu2005/SpektraLab/blob/b51e672/engine/resources_product/NOTICE.md) · [Upstream pair tests](https://github.com/JamesQiu2005/SpektraLab/blob/b51e672/engine/tests/portra_nc_vc_checks.py)

**Monochrome camera exposure shipped in batch 3.** RS now implements clear, No. 25 red and No. 29 deep red camera responses on monochrome stocks with optional neutral exposure compensation. The original recipe remains selectable. See the [photographic usage and results](USAGE.md#black-and-white-camera-filters). The [regression chart and resident border test](../crates/spektrafilm-core/tests/camera_filter.rs) cover Double-X on 2302, direct Tri-X reversal scanning, and stock-dependent exposure.

**Four silver negatives and graded paper shipped in batch 4.** The four films target three-emulsion Multigrade IV RC. RS fits its own TH-KG3 filter pack and midgray exposure for each full grade. Grade 5 reaches ISO R 57.30 against the published 40. All 28 CPU film/grade wedges were monotonic and their linear midgray rounded to 0.18403. Seven resident grades on one input produced one negative-cache miss and six hits. Compensated No. 25 red/blue separation passed on all four films. The CLI also printed one 512-pixel photographic preview on each stock and Tri-X on grades 00, 2, 4 and 5. Batch 5 traced the hard-end limit to the fitted emulsions and the head spectrum. Keep the full grades; revisit hard half steps if matching darkroom wedge measurements become available. Physical paper speed remains open. ## 4. Compare model changes before adopting a new look

| --- | --- |

A per-component grid or fitted pyramid would change sampling; revisit with a fixed-pitch phase sweep against the reference if a visible core or tail defect warrants it. [Point lights, photo timings and allocator measurements](ENGINE_STUDIES.md#resident-diffusion-reconstruction-batch-6) |
